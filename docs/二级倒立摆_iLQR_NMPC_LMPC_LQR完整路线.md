# 二级倒立摆完整控制路线

> 本文保留控制架构、算法关系和终端集等知识，作为扩展阅读。实际任务、完成标准与当前进度统一以 [工程计划.md](工程计划.md) 为准；不按本文的阶段编号维护版本记录。早期的手写连续动力学/RK4 路径属于可选学习，当前主线先复用 MuJoCo 离散预测。

## 1. 项目目标

本项目面向 MuJoCo 中的二级小车倒立摆，采用以下控制架构：

```text
大角度状态：iLQR / NMPC 摆起
        ↓
接近平衡：LMPC 约束平衡
        ↓
非常接近平衡：LQR 快速稳定
        ↓
任意控制器异常：LQR 兜底 + 输入限幅 + 安全保护
```

目标不是一开始就实现所有高级功能，而是让每个模块都能单独验证，最后再组合成完整控制器。

## 2. 系统模型

二级倒立摆包含小车和两根摆杆，常用状态为：

\[
x=[p,\dot p,\theta_1,\dot\theta_1,\theta_2,\dot\theta_2]^T
\]

其中：

- `p`：小车位置；
- `theta_1`：第一根摆杆角度；
- `theta_2`：第二杆相对第一杆的关节角，对应代码中的 `q2`；第二杆绝对角为 `theta_1+theta_2`；
- `u`：小车水平驱动力。

连续动力学写成：

\[
\dot{x}=f(x,u)
\]

离散控制模型写成：

\[
x_{k+1}=F(x_k,u_k)
\]

MuJoCo 负责真实仿真和状态推进，控制器内部的动力学模型负责预测未来状态。

## 4. 总体开发阶段

### 阶段 0：环境和 MuJoCo 模型

完成内容：

1. 建立二级倒立摆 XML；
2. 确认两个铰链的正方向和零角度；
3. 确认小车、两根摆杆和执行器的 ID；
4. 读取 `qpos`、`qvel`、控制输入和仿真时间；
5. 在 viewer 中手动观察模型运动。

验收标准：

- 能编译并启动 MuJoCo；
- 能打印六维状态；
- 能施加固定力并观察小车运动；
- 能明确“竖直向上”对应的角度值。

### 阶段 1：建立统一状态接口

定义统一状态结构：

```cpp
struct State {
    double position;
    double velocity;
    double theta1;
    double omega1;
    double theta2;
    double omega2;
};
```

统一状态顺序，读取时保留连续关节角，局部控制器另算周期角度误差；非线性优化使用平滑周期代价。所有控制器都只接收统一的六维状态，不直接访问 MuJoCo 的内部数组。

验收标准：从 MuJoCo 读取的状态与 viewer 中的运动方向一致，角度正负号没有反向问题。

### 阶段 2：动力学模型和离散化

实现：

```text
continuous_dynamics(x, u) -> x_dot
discrete_dynamics(x, u, dt) -> x_next
```

初期可以使用 RK4 离散化。模型参数必须来自 XML 或统一参数文件，包括质量、长度、质心、惯量、阻尼、摩擦和执行器比例。

验收标准：

- 无控制输入时，模型运动趋势与 MuJoCo 一致；
- 随机状态和随机输入下，离散模型没有 NaN；
- 轨迹误差在合理范围内，而不是追求不现实的 `1e-12` 单步误差。

### 阶段 3：线性化和 LQR

在目标平衡点附近计算：

\[
\delta x_{k+1}=A_d\delta x_k+B_d\delta u_k
\]

实现离散 Riccati 方程，得到：

\[
u=-K\delta x
\]

LQR 负责：

- 验证线性化模型；
- 作为接近平衡时的快速控制器；
- 作为 LMPC 的终端控制器；
- 作为 iLQR/NMPC 失败时的兜底控制器。

验收标准：从较小角度偏差开始，LQR 能将两根摆杆稳定到竖直位置，并且输入不持续饱和。

### 阶段 4：实现 LMPC 平衡控制器

LMPC 使用线性预测模型：

\[
x_{i+1}=A_dx_i+B_du_i
\]

典型目标函数为：

\[
J=\sum_{i=0}^{N-1}(x_i^TQx_i+u_i^TRu_i)+x_N^TPx_N
\]

其中 `P` 可以使用 LQR 的 Riccati 解。第一版只加入输入约束：

\[
u_{min}\leq u_i\leq u_{max}
\]

确认 LMPC 能够稳定后，再加入小车位置、摆角和速度约束。

验收标准：

- 无约束 LMPC 与 LQR 的行为接近；
- 加入输入限制后，控制输入不越界；
- QP 无解时能返回明确的失败状态；
- 控制周期内能完成计算。

### 阶段 5：实现 iLQR 摆起

iLQR 用于大角度非线性运动。每次控制周期执行：

```text
1. 获取当前状态
2. 生成控制序列初值
3. 前向滚动得到状态轨迹
4. 计算动力学导数和代价导数
5. 反向递推得到控制修正量
6. 线搜索并更新控制序列
7. 只执行第一个控制量
8. 下一个周期重新优化
```

代价函数应同时考虑：

- 两根摆杆接近竖直；
- 摆角速度减小；
- 小车不要跑出轨道；
- 控制输入不要过大；
- 最终状态接近平衡点。

第一版 iLQR 可以先只处理软约束和输入裁剪。需要明确：裁剪控制输入不等于严格约束 NMPC，只适合作为入门版本。

建议初始参数：

- 控制周期：先从 10–20 ms 实测；
- 预测步长：20–50；
- 迭代次数：5–20；
- 线搜索：使用多个缩放系数；
- 导数：先使用数值差分，稳定后再改为解析导数或自动微分。

验收标准：从多个大角度初始状态出发，iLQR 能够把系统带到 LQR 或 LMPC 的接管范围内。

### 阶段 6：从 iLQR 过渡到 NMPC

iLQR 主要解决无约束或软约束问题。加入严格输入、状态和轨道约束后，控制器才更接近 NMPC。

升级内容：

1. 使用带约束的优化器；
2. 把输入限制写入优化问题；
3. 加入小车位置和速度限制；
4. 加入摆角和角速度限制；
5. 对不可行问题设置软约束松弛变量；
6. 设置超时和最大迭代次数。

NMPC 的失败处理必须明确：

```text
优化成功且状态安全 -> 使用 NMPC 第一个控制量
优化超时或不可行   -> 使用上一拍有效控制或 LMPC
状态接近平衡       -> 切换 LMPC
LMPC 失败          -> 切换 LQR
状态异常           -> 安全滤波器和紧急限幅
```

### 阶段 7：设计模式切换器

不要只使用一个瞬时角度阈值，否则在边界附近可能频繁切换。建议使用进入阈值和退出阈值形成迟滞：

```text
进入平衡区：角度和角速度都小于较小阈值
退出平衡区：角度或角速度超过较大阈值
```

基本逻辑：

```text
如果状态异常：安全模式
否则如果平衡区内：LMPC
否则如果接近平衡：LMPC 或 LQR
否则：iLQR / NMPC 摆起
```

切换条件不能只看一个摆杆，应同时检查：

- 两根摆杆角度；
- 两根摆杆角速度；
- 小车位置；
- 小车速度；
- 控制输入余量。

### 阶段 8：加入 LQR 兜底和安全滤波

基础输入限幅、非有限值检查和轨道异常中止从仿真循环开始接入。以下 LQR 备用路径只适用于状态有效、且在已验证局部区域内的情况；异常测量不可直接送入 LQR，远离平衡也不能把 LQR 当作全局恢复控制器。

LQR 兜底至少处理以下情况：

- NMPC 超时；
- NMPC 不可行；
- 求解器返回 NaN；
- 模型预测发散；
- LMPC 求解失败；
- 传感器状态暂时异常。

安全滤波器至少执行：

```text
输入限幅
小车轨道限幅
状态 NaN 检查
最大速度检查
角度跳变检查
控制变化率限制
```

安全滤波器不负责完成摆起，它的职责是防止控制器把模型推入明显危险状态。

### 阶段 9：终端代价和终端集

当基本架构稳定后，再加入 LQR 终端控制器和终端椭球：

\[
\Omega=\{x:x^TPx\leq c\}
\]

需要验证：

1. `P` 对称正定；
2. 终端控制 `u=-Kx` 满足输入约束；
3. 终端状态满足位置、速度和角度约束；
4. 终端控制在该区域内确实能降低代价。

终端集是提高理论完整性和切换可靠性的功能，建议最后实现。

## 5. 最终控制循环

```text
读取 MuJoCo 状态
        ↓
角度归一化、状态检查
        ↓
判断当前模式
        ↓
大角度：运行 iLQR/NMPC
接近平衡：运行 LMPC
LMPC 失败：运行 LQR
状态异常：运行安全控制
        ↓
输入限幅和变化率限制
        ↓
发送控制量到 MuJoCo
        ↓
记录状态、输入、模式和计算时间
```

## 6. 推荐的验证顺序

以下是不同模块的检查内容，已纳入主计划相应任务；无需分别建立记录文件。

### 模型验证

- XML 能启动；
- 状态地址正确；
- 角度方向正确；
- 输入方向正确。

### 线性化验证

- 数值差分得到的 `A、B` 稳定；
- 特征值和物理直觉一致；
- 平衡点附近预测误差较小。

### LQR 验证

- 小角度初始状态能稳定；
- 输入不持续饱和；
- 改变 Q、R 后结果符合预期。

### LMPC 验证

- QP 能稳定求解；
- 输入约束有效；
- 失败时有明确兜底路径。

### iLQR 验证

- 无约束情况下能降低代价；
- 线搜索不会导致代价持续增大；
- 多个大角度初始状态能够接近平衡。

### 组合控制器验证

- iLQR/NMPC 能交给 LMPC；
- LMPC 能交给 LQR；
- 模式切换没有明显抖动；
- 失败时不会停止输出控制量。

### 鲁棒性验证

- 随机初始角度；
- 质量和长度存在误差；
- 添加阻尼和摩擦；
- 输入存在噪声；
- 求解器偶发超时。

## 8. 实施优先级

推荐按照以下顺序真正写代码：

```text
MuJoCo 接口
    ↓
统一状态结构
    ↓
动力学和离散化
    ↓
线性化
    ↓
LQR
    ↓
LMPC
    ↓
iLQR
    ↓
NMPC 约束
    ↓
模式切换
    ↓
安全滤波
    ↓
终端集和鲁棒性测试
```

不要在 LQR 尚未稳定前开始调 NMPC。否则出现问题时，很难判断是模型、线性化、代价函数、求解器还是模式切换导致的。

## 9. 最终判断

“iLQR/NMPC 摆起 + LMPC 平衡 + LQR 兜底”是一个全面且合理的最终架构，适合二级倒立摆的工程化实现。

它的关键不是一次性把所有模块写完，而是让每一层都可以独立运行：

```text
LQR 先证明平衡模型正确
LMPC 再处理约束
iLQR/NMPC 再处理大角度非线性
模式管理器负责切换
LQR 和安全滤波器负责兜底
```

这样既保留了完整方案的理论价值，也能让项目在每个阶段都得到可观察、可调试的结果。

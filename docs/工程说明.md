## 状态与角度

```text
x = [p, dp, q1, dq1, q2, dq2]
```

`q1` 对应 `pole_1_hinge`，是第一杆相对竖直向上的角度；`q2` 对应 `pole_2_hinge`，是第二杆相对第一杆的角度。第二杆绝对角为 `q1+q2`，绝对角速度为 `dq1+dq2`。两杆向上时两个关节角都为零。

位置/速度使用 m、m/s，关节角/角速度使用 rad、rad/s。两关节沿 +y 轴正转，杆的局部 +z 轴向世界 +x 偏转。实现时仍需通过姿态和运动检查确认。

`qpos` 和 `qvel` 是分别存放位置和速度的数组，统一状态是交错排列。按 joint 名称读取 `jnt_qposadr`、`jnt_dofadr`，不要直接拼接数组。原始角度保持连续；局部控制误差和大角度平滑代价分别处理。

## 物理模型和预测模型

仿真与初期预测均调用 MuJoCo，使用不同的 `mjData`，共享只读模型参数。未来预测不应改变实际仿真时间、状态或输入。

先通过 MuJoCo 离散状态转移的中心差分建立 A、B，与一阶工程一致。解析连续动力学和自写积分器作为扩展学习，避免同时排查控制器与手写模型。

XML 管理物理参数。当前 `config/default.yaml` 仅为占位，程序尚未读取；实际接入配置时再选择解析方法，避免出现“改了配置但运行不生效”。

## 时间与数据流

当前 XML 物理步长为 0.002 s。控制周期是输入更新间隔，可为整数个物理步；所有预测模型、线性化和控制器必须使用对应周期。

```text
运行参数与 XML
      ↓
模型接口 → 独立预测 → 数值线性化 → LQR / LMPC / SQP
      ↓                              ↓
实际六维状态 → 控制器/模式选择 → 输出检查与限幅
      ↑                              ↓
      └──────── MuJoCo 推进 ←─────────┘
                      ↓
                CSV → 曲线/展示
```

后续 SQP 控制器复用非线性预测。所有模式共用同一套状态定义、输入单位、主循环和日志格式。

## 模式与失败处理原则

大角度和约束场景用 SQP，平衡捕获区域用 LMPC 或 LQR。进入平衡模式的阈值小于退出阈值，并同时考虑两杆角度、角速度、小车位置和速度。

LQR 只能在验证过的局部区域内备用。状态非有限、远离平衡、靠近轨道端点等情况应由明确的异常处理决定，不保证任意故障都能靠 LQR 扶正。限幅和停止仿真是基础保护，不等同于严格安全保证。

## 日常输出

日志最初保留时间、六维状态、请求力和实际力；接入优化控制后再加入模式、求解状态与耗时。代价、迭代次数等按调试需要增加。

默认写入 `logs/run.csv` 和 `results/response.png`，重复实验允许覆盖，需要对比时指定其他文件名。自动输出与代码检查用于判断效果，不额外维护阶段报告。

# 工程说明：代码讲解版

本文件用于本项目的代码讲解。理论部分已经单独讲过，这里只回答：每个核心文件做什么、数据怎样流动、一次运行按什么顺序执行。算法核心详细说明，窗口、日志、脚本和测试只做简要介绍。

## 1. 先看完整运行主线

```text
main.cpp
  ↓
app/application.cpp：解析命令、加载模型、装配控制器
  ↓
model/dynamics：读取状态或推进独立预测数据
  ↓
model/linearize：需要局部模型时生成 A、B
  ↓
control / optimization：计算请求力
  ↓
app/viewer.cpp：限幅、施加外力、mj_step
  ↓
app/logger.cpp：记录 CSV，检查安全边界
```

所有控制器最后都被包装成同一种回调：读取 State，计算 requested_force，统一限幅后调用 mj_step。因此控制器的差别在“如何得到请求力”，而 MuJoCo 推进、限幅、日志和保护是共用的。

## 2. 目录和主线

```text
src/main.cpp                 极简启动入口
src/app/                     参数、装配、窗口、日志
src/model/                   状态、预测、线性化、诊断
src/control/                 LQR、LMPC、轨迹反馈、在线控制
src/optimization/            非线性预测、代价、SQP、通用 QP
include/                     对应接口
research/                    能量法和多重射击辅助代码
tests/                       功能测试和综合验收
tools/                       离线轨迹规划
config/plans/                正式运行轨迹
config/scenarios/            其他初始姿态轨迹
config/seeds/                SQP 初始猜测
```

讲解时重点看 model、control 和 optimization；其他目录最后简单介绍。

## 3. 启动和统一仿真循环

### src/main.cpp

只有一个职责：调用 run_application(argc, argv)。它保持很短，避免把启动入口和算法混在一起。

### src/app/application.cpp

这是应用装配层，负责解析命令、加载 XML、创建真实和预测 mjData、取得关节地址、执行模型诊断、选择控制器、配置日志和把控制器包装成反馈回调。这里不实现 Riccati、QP 或 SQP，只负责连接模块。

### src/app/viewer.cpp

窗口和无窗口模式共用同一套物理步：

```text
读取真实状态 → 检查有限值 → 调用控制器 → 执行器限幅
→ 写入外部推力 → mj_step → 读取新状态和写日志
→ 检查轨道、速度和 MuJoCo 警告
```

因此批量测试和可视化运行使用同一套控制逻辑。

## 4. 状态和 MuJoCo 接口

### include/types.hpp

统一状态为：

```text
[p, dp, q1, dq1, q2, dq2]
```

p/dp 是小车位置和速度，q1/dq1 是第一关节角和角速度，q2/dq2 是第二关节相对第一杆的角度和角速度。第二杆绝对角是 q1+q2，绝对角速度是 dq1+dq2。所有控制器都使用这个结构体，避免不同模块出现不同状态顺序。

### src/model/dynamics.cpp

read_state 按关节地址从 qpos/qvel 读取统一状态；predict_state 把候选状态写入独立 mjData，施加输入并推进若干物理步。预测不会修改真实仿真数据，这是线性化、LMPC 和 SQP 反复试探未来输入的基础。

## 5. 数值线性化和模型诊断

### src/model/linearize.cpp

linearize_discrete 对 MuJoCo 的离散状态转移做数值扰动，得到指定控制周期的 A 和 B。代码检查平衡状态、输入和差分步长，对每个状态分量做正负扰动形成 A 的列，再对输入做正负扰动形成 B。文件后半部分还提供状态和输入缩放。缩放只改善计算量级，最后仍转换回物理单位。

### src/model/diagnostics.cpp

这里集中放置平衡点残差、差分步长稳定性、线性与非线性预测对照、可控性矩阵 SVD、不同观察时域可控性和离散 PBH 可稳定性检查。可控性实现并入该文件，是因为这些检查共同回答“当前模型和局部线性化是否足以支持控制设计”。

## 6. LQR：固定平衡点的局部控制

### include/control/lqr.hpp

这里集中定义 LqrConfig 和 LqrResult。前者保存缩放、状态权重、输入权重和迭代参数；后者保存 Riccati 解、反馈增益、残差、对称性、正定性和闭环谱半径。

### src/control/lqr.cpp

solve_discrete_lqr 根据局部 A、B 迭代得到 P 和 K；compute_lqr_force 根据实际状态计算请求力。代码还检查输入和权重、Riccati 残差、P 的对称性和最小特征值、闭环谱半径。运行阶段这里只计算请求力，限幅由 viewer 统一完成。

讲解定位：LQR 是直立附近的局部平衡器，不是从完全下垂状态起摆的控制器。

## 7. LMPC：线性预测和约束 QP

### include/control/lmpc.hpp

接口按使用顺序集中放置：LmpcConfig 保存预测长度、缩放和边界；LmpcPrediction 保存预测状态；LmpcQpProblem 保存 Hessian、梯度和约束；LmpcQpSolution 保存解和最优性残差；LmpcControlResult 保存主循环需要的第一步力。

### src/control/lmpc.cpp

用缩放后的局部 A、B 预测未来 20 步，调用 QP 构造和求解，把最优输入序列第一项转换成实际力。每次只执行第一步，下一次用真实状态重新计算，这就是滚动优化。

### src/control/lmpc_qp.cpp

它先把状态、输入和终端项展开成输入序列上的二次目标，再把输入、位置、车速和关节速度边界写成线性约束，最后调用通用 QP 并检查可行性、驻点和互补性。LMPC 的定位是直立附近的受约束预测控制，不承担大角度起摆。

## 8. 非线性预测和代价

### src/optimization/nonlinear_model.cpp

predict_nonlinear_horizon 给定初态和力序列，用 MuJoCo 生成完整非线性轨迹；linearize_nmpc_trajectory 沿候选轨迹计算每段局部状态转移和输入导数。它不决定最优输入，而是为 SQP 提供模型、预测和导数接口。

### src/optimization/nmpc_cost.cpp

定义 SQP 的轨迹代价，包括小车位置和速度、两杆绝对角和绝对角速度、输入大小、输入变化以及终端状态。角度代价采用周期形式，避免转过一周后的直立姿态被原始角度误判为远离目标。LQR/LMPC 的局部权重和 SQP 的起摆权重是两套配置。

## 9. dense_qp：两个优化器共用的底层

### src/optimization/dense_qp.cpp

这是通用稠密凸 QP 求解器，不理解倒立摆。输入是 Hessian、梯度、变量边界和线性约束，输出是变量、目标值、约束残差、驻点残差和互补残差。

它负责有限值和矩阵检查、输入边界与耦合约束、主动集或对偶迭代、迭代上限和软时间预算，以及 KKT 相关残差判断。LMPC 直接使用它；SQP 把局部二次子问题转换后也使用它。

## 10. SQP：非线性起摆的算法核心

### include/optimization/sqp_solver.hpp

SqpConfig 保存最大迭代、控制分段、正则化、信赖域、线搜索、QP 上限、轨道/速度约束和时间预算。SqpResult 除了输入序列，还记录可行性、接受步数、代价变化、QP 残差、约束违反、耗时和停止状态。

### src/optimization/sqp_solver.cpp

一次 solve_nmpc_sqp 的代码顺序是：

1. 检查初态、力序列和参数；
2. 用非线性预测得到当前候选轨迹；
3. 计算状态、输入、输入变化和终端代价；
4. 检查每个物理步的输入、位置和速度约束；
5. 计算局部 A/B 以及残差导数；
6. 用链式法则传播输入对未来状态的影响；
7. 由 Jacobian 构造 Gauss–Newton QP；
8. 加入正则化和信赖域；
9. 调用 dense_qp 得到输入修正；
10. 线搜索尝试新序列；
11. 用完整非线性模型回滚检查新序列；
12. 根据收敛、可行性、迭代上限或预算返回结果。

重点是：它不是把输入相互独立地逐个调节。早期输入会影响后面很多状态，链式灵敏度保留了这种耦合关系。信赖域限制局部更新幅度，线搜索检查实际非线性代价，正则化改善数值条件，软预算避免采用过慢结果。这些机制提升局部优化可靠性，但不提供全局最优保证。

## 11. 轨迹规划、反馈和接管

### tools/plan_swingup.cpp

这是离线程序，不属于实时控制循环。它读取 config/seeds 中的力序列，调用 SQP 优化 50 段、总计 4 s 的起摆轨迹，然后检查末端捕获和连续 MuJoCo 重放后的 6 s LQR 稳定。两项都通过才写出正式轨迹，正式运行文件放在 config/plans。

### src/control/trajectory.cpp

它把 CSV 轨迹变成闭环控制器：读取并检查时间和力范围；用独立 MuJoCo 数据把 0.08 s 节点补成 0.002 s 物理步参考；沿参考轨迹反向递推有限时域 Riccati；预计算每个物理步的时变反馈增益；根据真实状态误差计算参考推力加反馈修正。

它还比较模型重放状态和 CSV 节点状态。模型改变后轨迹不一致，程序拒绝启动。反馈只在局部误差保护范围内工作，大偏离会停止。

### src/control/online_sqp_controller.cpp

在线模式以已验证轨迹为种子，每 0.08 s 删除已执行的第一段输入，从真实状态重新优化剩余序列，缩短未来时域，在两次更新之间用段内反馈修正，并记录优化是否采用和实际耗时。

结果分为：

| selected | 含义 |
|---|---|
| sqp | 新结果可行并采用 |
| feasible_warm_start | 新更新不可用，但暖启动序列重新验证后可行 |
| trajectory_feedback | 超时或无可行序列，回到原始 TVLQR |

4 s 结束时仍必须用真实状态通过捕获检查，才切换到平衡 LQR。

## 12. 命令与核心文件对应关系

| 命令 | 主要代码 | 定位 |
|---|---|---|
| --lqr | control/lqr.cpp | 固定直立点局部平衡 |
| --lmpc | control/lmpc.cpp、lmpc_qp.cpp、dense_qp.cpp | 局部线性预测与约束 |
| --plan FILE | control/trajectory.cpp 的前馈读取 | 纯前馈对照 |
| --track-plan FILE | trajectory.cpp + LQR | 推荐正式演示 |
| --online-plan FILE | online_sqp_controller.cpp + sqp_solver.cpp | 在线再优化实验 |
| --sqp | sqp_solver.cpp | 基线实验 |
| --swingup | research/swingup_controller.cpp | 能量法对照 |

推荐演示：

```powershell
.\\run.bat --track-plan config/plans/sqp_swingup.csv --duration 10
```

## 14. 建议现场讲解顺序

1. 先运行 --track-plan，说明最终控制效果；
2. 看 main.cpp 和 application.cpp，说明模块如何装配；
3. 看 types.hpp、dynamics.cpp，说明状态和独立预测；
4. 看 linearize.cpp、diagnostics.cpp，说明局部模型如何进入控制；
5. 重点讲 lqr.cpp、lmpc.cpp/lmpc_qp.cpp；
6. 重点讲 nonlinear_model.cpp、nmpc_cost.cpp、dense_qp.cpp、sqp_solver.cpp；
7. 最后看 trajectory.cpp 和 online_sqp_controller.cpp，说明怎样形成最终闭环；
8. 用 viewer、logger、tests 简单收尾。

讲解主线始终围绕：

```text
统一状态
→ 独立预测
→ 线性化或非线性轨迹评估
→ LQR / LMPC / SQP
→ 返回第一步请求力
→ 统一限幅、推进、日志和保护
```

## 15. 当前验证结论

当前工程已完成明示模型和场景下的闭环验证：

- 19 项 CTest 全部通过；
- 综合验收内部 30 个场景全部通过；
- 快速测试入口为 python tests/run_all.py --quick；
- 完整检查入口为 .\\check.bat。

这些结果说明代码接口、控制流程和已声明场景能够协同工作。在线 SQP 当前平均耗时仍高于 80 ms 控制周期，任意初态全局起摆、严格鲁棒约束和硬实时控制不属于已经证明的能力。
